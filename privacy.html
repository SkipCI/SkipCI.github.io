Privacy Policy

Last updated: 5 September 2026

SkipCI ("the application") is a private video production tool operated by Roman Neganov. This policy explains what data the application touches, why, and how long it keeps it. The application uses the YouTube API Services to publish videos to the YouTube channel its operator has connected.

1. Who runs the application

The application is run by its owner on their own machine. It has no public sign-up, no user accounts and no hosted backend that stores data for other people. The only person who connects an account to it is its operator.

2. What data the application accesses

  • Google account identity. When the operator signs in with Google, the application receives the basic profile information Google returns with the sign-in, so it can show which account is connected.
  • YouTube channel access, through the YouTube API Services. With the operator's consent, the application receives permission to upload videos to, and manage the metadata of, the operator's own YouTube channel.
  • Content the application itself produced. Video files, cover images, titles, descriptions and post texts generated by the pipeline.

The application does not read private messages, contacts, calendars, files in Google Drive, or any other Google data outside the scopes listed on the consent screen.

3. Why the data is used

Access to the YouTube API Services is used for exactly one purpose: publishing the videos the application produced to the channel the operator connected, and reading back the status of those uploads. The data is not used for advertising, profiling, resale, model training, or any purpose unrelated to that publishing step.

4. YouTube API Services

The application uses the YouTube API Services. By using it, the operator agrees to be bound by the YouTube Terms of Service, and their data handled by YouTube and Google is governed by the Google Privacy Policy (https://policies.google.com/privacy).

Access granted to the application through the YouTube API Services can be withdrawn at any moment on the Google security settings page: https://security.google.com/settings/security/permissions (also reachable at myaccount.google.com/permissions). Once revoked, the application can no longer reach the channel.

5. Google API Services Limited Use

The application's use of information received from the YouTube API Services and other Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Data obtained through the YouTube API Services is not transferred to third parties except as needed to provide the publishing feature, and is never sold.

6. Sharing

No data is sold, rented or shared with advertisers or data brokers. Data reaches third parties only where the operator explicitly asked for publication — for example, a video uploaded to YouTube becomes subject to YouTube's own terms and privacy policy, and a post sent to Telegram becomes subject to Telegram's.

7. Data storage, retention and deletion

What is stored. Two things, and nothing else: the OAuth credentials (access and refresh token) for the YouTube channel the operator connected, and the media the application itself produced — video files, cover images and their metadata.

Where it is stored. On the local disk of the operator's own machine, inside the operator's user account. There is no server, no shared database, no cloud storage and no third-party backup holding this data.

How long it is kept. Tokens are kept until access is revoked or the local credential store is deleted, whichever happens first. Produced media is kept until the operator deletes it. Data obtained from the YouTube API Services is not stored beyond what the current publishing step needs, and any such stored data is deleted no later than 30 days after it is fetched, unless it is refreshed from the API.

How it is deleted. Revoking access at myaccount.google.com/permissions invalidates the tokens immediately; deleting the local credential store removes the stored copy; deleting a run's folder removes its video, cover and metadata. Deletion is permanent — the files are removed from disk and there is no other copy to restore them from.

Deletion on request. A request sent to roman.neganov@gmail.com asking for stored data to be deleted is carried out within 30 days, and the sender is told once it is done.

8. Children

The application is not directed at children and is not usable by anyone other than its operator.

9. Changes

If this policy changes, the new version is published on this page with a new date at the top.

10. Contact
